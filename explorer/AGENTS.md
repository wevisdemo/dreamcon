# Dreamcon Explorer

Applies on top of the root `AGENTS.md`. Paths are relative to this package.

## Guideline

- [TanStack Start](https://tanstack.com/start) with file-based routing: one file per route in `src/routes/`, `__root.tsx` holds the HTML shell and `<head>`
- `src/route-tree.gen.ts` is generated by the Vite plugin on `dev`/`build` (path set by `router.generatedRouteTree` in `vite.config.ts`); commit it, never edit it by hand
- Every file and folder is named in kebab-case, except names a tool requires and can't be configured (`__root.tsx`, `AGENTS.md`, `README.md`)
- `src/` layout: `routes/` for pages, `components/` for shared UI, `icons/` for SVG icons as React components (`fill="currentColor"` so they follow the parent text color), `assets/` for images used as-is (like logos), `constants/` for static values (like `menus.ts`), `data/` for datasets, `utils/` for pure helper functions documented with JSDoc
- Typography utilities (`text-h*`, `text-b*` in `styles.css`) already switch size at `md`, so give an element a single text class and never swap it per breakpoint (no `text-h8 md:text-h10`). Pick the class whose desktop size matches the design
- `__root.tsx` renders the navbar and footer around every page inside `<main>`, so pages render a plain wrapper instead of their own `<main>`
- The site is statically prerendered at build time (`prerender` in `vite.config.ts`) and deployed as plain files from `dist/client/`; there is no server at runtime, so no server functions or request-time data. Routes with path params are only prerendered when linked from another page
- Data comes from the CSVs on the `published-data` branch of this repo (events, topics, comments) and of [`wevisdemo/dreamcon-data`](https://github.com/wevisdemo/dreamcon-data) (topic groups and group questions). `getConversations` merges topics, their groups and their comment threads (replies nested under `comments` at any depth) into one tree. Only topics the ML grouped (present in `topic_groups`) are shown; the editor's `categories` column is ML input and never read. Data is fetched from GitHub and parsed with sheethuahua in `src/data/`: one file per dataset (`events.ts`, `conversations.ts`, `group-questions.ts`) holding its schemas, types and a cached `load*` function free of TanStack imports, with shared helpers in `shared.ts`. `server-functions.ts` wraps those loaders in `staticFunctionMiddleware` server functions, and `vite.config.ts` imports the plain loaders directly (to list topic pages to prerender, and to emit `dreamcon-data.zip` from `dataset-zip.ts` as a build asset, since prerender writes responses as text and would corrupt binary files). Load data in route loaders only through those server functions: they run at build time (and once per dev server start in dev, so restart it for fresh data) and production reads their prerendered JSON, so never fetch the CSVs from a component or a plain loader, which would run in the browser. Every route's loader data is embedded in its HTML, so load only the datasets the route needs
- Route components render at build time too: keep browser-only APIs (`window`, `localStorage`) inside effects or event handlers
- Agent skills live in `.claude/skills/`. When an installed package ships its own skills (like TanStack), symlink the skill directory from `node_modules` so it matches the installed version; these need `pnpm install` before they resolve. Install other skills with the [`skills` CLI](https://github.com/vercel-labs/skills) (`npx skills add <owner>/<repo>`)
- No e2e tests: the root `pnpm test` doesn't cover this package, so verify changes with `pnpm build`
